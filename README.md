# ГАРАНТ — маркетплейс с эскроу

Учебный сайт на чистом PHP и MySQL. Платформа замораживает оплату покупателя и переводит её продавцу только после подтверждения получения. Обмен закрывается после подтверждения обеих сторон.

## Установка

1. Нужны PHP 8.0+ (PDO MySQL, mbstring, fileinfo) и MySQL 8 или MariaDB. В Open Server это уже есть: положите проект в `domains/GARANT`.
2. Запустите MySQL. В типовом Open Server логин `root`, пароль пустой, порт `3306`.
3. Импортируйте схему. Повторный импорт удаляет данные только базы `garant`.

```bat
C:\OSPanel\modules\database\MySQL-8.0-Win10\bin\mysql.exe -u root < C:\OSPanel\domains\GARANT\sql\schema.sql
```

В HeidiSQL: файл `sql/schema.sql`, выполнить.
4. Откройте `config.php` и проверьте `DB_HOST`, `DB_PORT`, `DB_NAME`, `DB_USER`, `DB_PASS`.
5. Перезапустите Open Server, чтобы появился домен. Сайт откроется как `http://garant/`. Папки `uploads/` и `storage/` создаются сами и должны быть доступны на запись.
6. На публичном сервере в `config.php` поставьте `SHOW_DEMO_HINTS` и `APP_DEBUG` в `false`, смените `CRON_KEY` и пароли учебных аккаунтов.

Каталог и карточки товаров открыты без входа. Оформление сделки, кабинет, переписка и админка — только после входа.

## Как проходит сделка

1. Покупатель оформляет заказ. Для продажи в `escrow_transactions` пишется `hold`, одна единица товара снимается с витрины. Статус: «Оплачено (заморожено)». У обмена денег нет, статус: «Зафиксировано гарантом».
2. Продавец нажимает «Товар отправлен». Статус «Отправлено», начинается срок `ESCROW_DAYS` (по умолчанию 7 дней).
3. Покупатель подтверждает получение. Для продажи пишется `release`, статус «Завершено». Для обмена статус становится «Подтверждено», и продавец ещё подтверждает встречный товар.
4. До отправки любая сторона может отменить сделку: `refund` и возврат товара в наличие.
5. После отправки вместо отмены открывается спор. Деньги остаются замороженными, пока администратор не выберет возврат или перевод продавцу.
6. Если срок вышел, `includes/escrow.php` само переводит сделку в спор. Константа `ESCROW_ON_TIMEOUT = refund` включает автовозврат. Обмен, где одна сторона уже подтвердила, всегда уходит в спор.
7. Отзыв 1–5 доступен только из статуса «Завершено», один раз от каждой стороны. Рейтинг роли — среднее таких оценок. Пока отзывов нет, в профиле стоит стартовое 5.0, и эта пятёрка в среднее не входит.

Просрочка проверяется при каждом заходе на сайт. Отдельно можно дернуть `cron.php?key=garant-local-cron` — ключ лежит в `config.php`.

## Почта и карта

Код второго шага входа уходит через `mail()` и всегда копируется в `storage/outbox/`. На локальном Open Server письмо часто не уходит наружу: код читают из этого файла.

Форма карты учебная. После проверки Луна сохраняются бренд, имя, срок и последние 4 цифры. Полный номер не пишется в базу и не попадает в журнал ошибок. Для проверки: `4242 4242 4242 4242`, срок в будущем, например `12/28`.

## Защита

- SQL только через PDO и плейсхолдеры, без эмуляции подстановки.
- Вывод текста через `e()` / `htmlspecialchars`.
- На всех изменяющих формах скрытое поле CSRF, проверка через `hash_equals`.
- Пароли — `password_hash` / `password_verify`. После входа сессия пересоздаётся.
- Загрузка фото: MIME и `getimagesize`, своё случайное имя, в `uploads/` запрещено исполнять PHP.
- Прямой HTTP-доступ к `config.php`, `includes/`, `sql/` и `storage/` закрыт через `.htaccess`.
